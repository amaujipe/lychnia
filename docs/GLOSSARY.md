# Glossary: original pipeline (Spanish) to Lychnia (English)

> Used to translate the repo on 2026-09-04 and to keep identifiers consistent when migrating scripts from `multimedia-iglesia-tunja`. The left side is what the original scripts, TOML and Makefile call things; the right side is what Lychnia calls them.

## Project and process
- Motor → Engine (sub-project 1)
- orquestador → orchestrator
- tarea → task; objetivo compuesto → composite target
- artefacto → artifact; artefacto aportado → provided artifact (supplied by a person or the Writer, not generated by a task)
- huella → fingerprint
- corrida → run
- Gate A / Gate B → Gate A / Gate B (keep)
- asistente (herramienta que devuelve números) → assistant (helper command)
- capacidades del equipo → machine capabilities
- proveedor → provider: Transcriptor → Transcriber, Redactor → Writer, Biblia → Bible, Detector → Detector
- cáscara (Tauri) → shell
- paquete de modelos → model bundle
- prédica → sermon; predicador / pastor → preacher (keep "pastor" only in quotes)
- iglesia → church; Iglesia de Tunja → Iglesia de Tunja (proper name, keep)
- bitácora → journal (file: docs/JOURNAL.md)
- spike → spike
- regla dura → hard rule
- repo original → original repo (`multimedia-iglesia-tunja`)

## Media and pipeline
- maestro (grabación principal de OBS) → master recording (short: master)
- Cam A panorámica → Cam A (wide shot); Cam B pastor → Cam B (preacher)
- ENTREGA/ (carpeta que llena el operador) → input/ (folder name in Lychnia projects); when referring to the original repo keep `ENTREGA/`
- transcripción → transcript / transcription
- sincronía, offset → sync, offset; t_camara = t_maestro + off → t_camera = t_master + offset
- corte (entrada / salida) → cut (in / out): `cut.start`, `cut.end`
- plan de cámaras, planos → camera plan, shots; fases → phases; plano largo / de descanso → long shot / rest shot
- imantar al silencio → snap to the nearest silence
- rejilla de 1/30 s → 1/30 s frame grid; frame-exacto → frame-exact
- Fase 1 (segmentos) / Fase 2 (render final) → Phase 1 (segments) / Phase 2 (final render)
- callouts → callouts; versículo → verse; lower-third → lower-third; pantalla completa → full screen; frase clave → key quote; punto → outline point; lista progresiva → progressive list
- ancla (al SRT) → anchor
- guion (guion.md) → outline (outline.md)
- clip de muestra → preview clip (task `preview`)
- frames de control / hojas de contacto → control frames / contact sheets
- cadena de voz → voice chain; mezcla (dual-mono/izquierdo/derecho) → downmix (dual-mono/left/right); retardo → delay; LUFS → LUFS
- subtítulos → subtitles; shorts → shorts; miniatura → thumbnail; fondo (IA) → background (AI-generated); portada → thumbnail
- metadata de YouTube → YouTube metadata; blog → blog post
- salud de cámaras → camera health
- huella_video / huella_audio / huella_corte → video_fingerprint / audio_fingerprint / cut_fingerprint
- LIMITE_MASTER → MASTER_LIMIT (env var), `limit` (API field)
- "Propuesta C" (estética) → "Proposal C" (keep as a proper name)
- Pescaseo, SEOMARCO, etc. (CreceTube) → keep as proper names

## Identifiers (English, snake_case in Python, kebab-case in CLI)
- tasks: init, transcribe, camera_health, plan, callouts, control_frames, segments, preview, render, subtitles, shorts, thumbnail, blog
- composite targets: prepare, gate_a, video, content, deliver
- CLI: `lychnia serve | capabilities | new | status | config | run | provide | approve | assist | log`
- API: /system/capabilities, /projects, /projects/{id}, /config, /status, /run, /cancel, /artifacts, /artifacts/{name}/approve, /assistants/{name}, /runs/{run}/log, WS /events
- package layout: lychnia/{cli.py, api/, orchestrator/, project/, tasks/, media/, text/, providers/, resources/, i18n/}
- state dir: `.lychnia/state.sqlite`, `.lychnia/logs/`
- config file: `project.toml` with English keys: [meta] date, slug, title, passage, preacher, author_id; [sources] master, cam_a, cam_b; [sync] offset_a, offset_b, audio_delay_ms; [cut] start, end; [video] vf_a, vf_b; [audio] downmix, lufs; [gate_b] start, duration; [[shorts]] id, start, end, keyword, title; [shorts_overrides.<id>]; [plan] closing_a, [[plan.phases]] start, end, cam, long_shot, rest_shot, note; [thumbnail] headline, subtitle, mode, with_face, ai_background; [publishing] thumbnail_url, youtube_id
- project folder layout for Lychnia projects: input/{audio,cam-wide,cam-preacher,photos,INFO.md}, transcript/, outline/, video/, youtube/, blog/, project.toml, .lychnia/
- artifact logical names: transcript.srt/.tsv, camera_health.txt, camera_plan.json, outline.md, callouts.toml, callouts.ass, callouts_render.ass, segments.txt, preview.mp4, final.mp4, final.srt, shorts/<id>.mp4, thumbnail.jpg, <slug>.src.mdx, <slug>.mdx, youtube.md, shorts-metadata.md, background.png, background-prompt.md
- fixtures keep their legacy Spanish file names (predica.srt, proyecto.toml, …); the fixtures README explains it

## Operator-facing text (Spanish via i18n — exception 3 of the global language policy)
- CLI/UI messages, error messages for operators, template comments in project.toml and INFO.md live in translation files (`lychnia/i18n/es.toml` default, `en.toml`), never inline in code. Developer-facing logs and exceptions' internal messages are English.

## Style
- Plain, direct English. No em dashes. Keep tables. Keep code blocks and file paths exact.
- Dates ISO. People: Andrés (user) — refer to him by name; "the user" is fine too.
- Do not invent facts; if a Spanish sentence records a decision, translate it faithfully.
